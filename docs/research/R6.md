# R6 — Reference repository reuse

Research date: 2026-10-06. **Recommendation:** adapt the paired STM32/gateway UART separation, the Nucleo ISR-to-task notification pattern, and NXP’s separation of measurement from statistics output. None is a ready-made deadline-supervision protocol.

**Scope and evidence.** Read `PROJECT.md` and `AGENTS.md` in full before review. Project §§1, 3, 5–6 motivate scheduling, bounded communication, freshness and fault-detection experiments; §2 leaves wiring/baud open. AGENTS §§3–4 prohibit adopting the references’ ROS2/Yocto/container/Ethernet stack or modifying submodules. Sources below were read locally under the authorized main checkout’s `third_party/`; all paths are relative to that directory. Every cited README and implementation file was read in full, including sections beyond those cited. URLs pin the inspected commits; no claim about newer upstream versions is made.

## Reuse table

| Area / reference paths and exact sections | SOURCE — observed behavior | IMPLICATION — course-project adaptation |
|---|---|---|
| **UART framing, STM32.** [S1] `stm32-machine-io-node/README.md`, “UART Commands”, “UART Responses”, “UART Settings”; `Core/Src/main.c`, `StartUartRxTask`, `StartCommandTask`; `Core/Inc/shared_types.h`, `CommandMessage`; `Core/Src/protocol.c`, `Protocol_HandleCommand`. | Receiver ignores CR, terminates on LF, assembles a 64-byte buffer and copies commands into an eight-entry queue. Handler emits ACK/NACK/STATUS with CRLF using bounded `snprintf`. RX is polling `HAL_UART_Receive(..., 1, 10)`, not DMA/interrupt reception. Overflow resets the index immediately; queue-put status and formatting truncation are unchecked. These paths contain no CRC, sequence or acquisition timestamp. | Reuse the separation of byte assembly, message delivery and command handling in `protocol/` and `stm32/`. Treat text framing as a baseline candidate only. Discard an overlong frame through its delimiter; count queue drops and truncation. A bounded integrity/freshness format needs a separate design decision to support corruption and AoI experiments (§5), rather than copying these machine-control fields. |
| **UART gateway.** [S2] `machine-monitoring-edge-gateway/meta-anas-edge/recipes-apps/edge-gateway/files/manager/uartManager.cpp`, `configureUartDevice`, `writeLine`, `readLine`; sibling `protocolParser.cpp`, `isAckandPing`, `parseStatus`. | Raw termios config uses 115200/8N1; writes append LF; reads skip CR and stop at LF. Each byte gets a new 1000-ms `poll` timeout and the string has no length cap. `writeLine` accepts any nonnegative write, including a short write. Parser requires 14 conversions but does not enforce complete consumption; PING recognition is a prefix match. | Adapt device/configuration and parser boundaries into `linux/`, with configurable UART parameters. Require a frame-length cap, whole-frame deadline, complete-write loop and exact field/range validation. These expose bounded I/O and error accounting without importing ROS2 or Yocto. A bytewise timeout alone does not bound a continuously arriving malformed frame. |
| **FreeRTOS task layout.** [S1] README “Firmware Tasks”; `Core/Src/main.c`, task attributes, `main`, `StartCommandTask`, `StartTelemetryTask`; `Core/Src/freertos.c`, “Private application code”. | Actual task creation is in `main.c`; `freertos.c` is an empty scaffold. RX has AboveNormal priority, commands Normal and telemetry Low; each application task has a 2048-byte stack. A telemetry mutex protects snapshot/state work, including protocol handling. TX uses `HAL_MAX_DELAY`; telemetry ends with relative `osDelay(100)`. | Adapt producer/consumer roles and bounded message copies, not the priority/stack constants. Give deadline supervision an independent periodic task with justified priority and absolute periodic release; bound critical sections and TX waits. Measure execution time, stack use and queue pressure before choosing priorities. This makes scheduling and failsafe latency observable (§§3, 5–6). |
| **ISR handoff.** [S3] `nucleo-f446re-freertos/004LEDsNotifyISR/README.md`, opening purpose paragraphs; `004LEDsNotifyISR/src/main.c`, `EXTI15_10_Handler`, `LED1_handler`–`LED3_handler`; root README “Debugging”. | ISR passes a higher-priority-task-woken flag to `xTaskNotifyFromISR` and `portYIELD_FROM_ISR`; tasks block in `xTaskNotifyWait`. However, the ISR first calls busy-wait `Delay(200)` and can notify a NULL handle after all LEDs finish. SystemView tracing uses USART2. | Reuse notification/yield mechanics for waking a UART worker; keep ISR bounded, validate handles and defer debounce/work. Notifications signal availability, while a bounded buffer retains bytes. Do not copy task deletion or ISR delay. Trace UART use must be reconciled with still-TBD board routing; tracing overhead needs measurement. |
| **Gateway logging/recovery.** [S2] root README “Robust Startup Behavior”, “systemd Services”; gateway `files/main.cpp`, global log, `handleIncomingIpcData`, `main`; `files/edge-gateway.service`, `[Service]`. | App appends command/reply/error text to `/var/log/edge-gateway.log`, flushing with `std::endl`. No timestamps, sequence IDs, rotation or log-open check appear there. Service restarts after 5 s. Polling/commands use a UART mutex, but handshake does not; log writes also lack a common lock. Failed reads return polling to handshake. | Adapt lifecycle/error events and systemd restart behavior on Ubuntu. Use structured records with run/sequence IDs, monotonic event times, outcome and drop counters; define bounded logging and compare logging-on/off latency. Serialize all UART transactions. Restart/reconnect is recovery, not proof of MCU watchdog response. |
| **Measurement/task separation, NXP.** [S4] `heterogeneous-multicore/README.md`, “Overview”, “Applications → RTOS Benchmark” and “RPMSG Applications”; `apps/rt_latency/freertos/main.c`, `start_test_case`, `log_task`; `apps/rt_latency/common/rt_latency.c`, `latency_alarm_handler`, `rt_latency_test`, `print_stats`. | Benchmark task outranks load/log tasks. Alarm callback records IRQ time and releases a semaphore; benchmark records wake time and accumulates statistics/histograms, with periodic snapshot output. README’s UART-sharing application transports access via RPMsg/SRTM on NXP multicore platforms. | Reuse measurement stages and deferred summaries to separate UART arrival, task dispatch and supervisor action. Port concepts only: NXP counters, board support and shared-memory RPMsg/VirtIO transport do not implement the external Pi–STM32 UART bridge. Local IRQ/scheduler latency is not end-to-end AoI; cross-device timestamps require an explicit clock/offset method. |
