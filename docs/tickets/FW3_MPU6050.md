# FW3: MPU6050 periodic sampling task

## Scope and implementation

FW3 adds an optional STM32F446RE sampling task for OS-T7. Build the default image
with `IMU=0` (default), or the bench image with `IMU=1`. The IMU task uses a
static 512-word stack, FreeRTOS idle priority 0, and `vTaskDelayUntil` at 200 Hz;
the supervisor stays priority 3 and UART RX stays priority 2. This gives the
experiment a lower-priority periodic workload beneath supervisor, RX, and status
TX (priority 1) while preserving their scheduling precedence. The periodic task
blocks between releases, so it does not starve the idle task. It does not alter
UART framing, the supervisor state machine, or its policy.

I2C1 is configured directly through registers on PB6/SCL and PB7/SDA (AF4,
400 kHz, open drain, external pull-ups). At startup the driver checks WHO_AM_I
register 0x75 for 0x68 and wakes the sensor. Each successful sample reads the
14-byte burst beginning at 0x3B. `imu_state` provides raw and scaled values,
the sample's DWT CYCCNT, saturating I2C/sample/missed-period counters, and an
eight-bin histogram of absolute release-period error (10 microsecond bins,
last bin is overflow). The pure host parser tests big-endian signed values and
the default ±2 g, ±250 degree/s, and temperature conversions.

## Build and host check (Mac)

```sh
make -C stm32/firmware firmware CLOCK_SOURCE=HSE RX_MODE=DMA UART_BAUD=921600
make -C stm32/firmware firmware CLOCK_SOURCE=HSE RX_MODE=DMA UART_BAUD=921600 IMU=1
make -C stm32 test
```

Save each `arm-none-eabi-size` result (`text`, `data`, `bss`) for the default and
IMU images in `logs/FW3-summary.md`. These builds and the host parser test do
not validate I2C electrical behavior or FreeRTOS timing on hardware.

## OS-T7 bench procedure

Use a known MPU6050 breakout, power off while wiring, and use 3.3 V logic with
common ground. Connect sensor VCC to 3V3, GND to GND, SCL to PB6 (Arduino D10 /
CN7-21), SDA to PB7 (I2C1 AF4 header pin), and leave AD0 low so the address is
0x68. Confirm the breakout has suitable pull-ups to 3.3 V; do not connect a
5 V pull-up. Check the exact board revision/header silkscreen and sensor board
pin labels before powering. Build the `IMU=1` image, then follow the project's
approved firmware loading procedure; this ticket does not authorize or perform
a flash.

Run OS-T7 from `docs/TEST_SCENARIOS.md` for three configurations: idle link,
back-to-back valid frames at maximum supported rate, and corrupted-frame bursts.
For each configuration, collect `imu_state.sample_cycles`, the jitter histogram,
`missed_periods`, `sample_errors`, and `i2c_errors` over the same run window as
the UART workload. Record supervisor reaction time and compare it with OS-T6.
Use 84 MHz DWT cycles (divide by 84 for microseconds) and compute P99 from the
period error histogram, preserving raw counts. Store raw capture and metadata
under `results/<YYYY-MM-DD>_os_t7_rtos_load/`, with a separate run/config label
for each workload. Pass criteria are those in OS-T7: P99 period jitter <100 us,
zero missed samples in all three configurations, and unchanged OS-T6 reaction
times. A Mac build cannot establish those criteria; they require the physical
bench and logic/scheduling observations.
