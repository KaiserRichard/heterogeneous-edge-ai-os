## Contention key and exact retained commands (page 9)

These are treatment definitions, not measured memory-bandwidth or cache-isolation claims. The timer uses CPU 0 with locked memory. The E1–E3 pipeline uses inference CPU 0, source/bridge CPU 1. Model-only inference allows CPUs 0–3 with CPU stress on 2/3. CPU and Memrate use CPUs 2/3; Stream and Cache use CPU 2. Stream index 0 performs sequential copy/scale/add/triad operations; the `2M` L3-size argument controls allocation sizing, not a 2 MiB total array. Cache selects a `2M` working set; it does not guarantee a particular cache residency. Memrate uses `64M` buffers and no requested rate cap.

Retained timer commands: `results/2026-10-11_cyclictest/20261008T091937Z_cyc_P0/<condition>_r1/stress_cmd.txt`:

```sh
# Linux target only; retained commands, not executed during deck revision.
taskset -c 2,3 stress-ng --cpu 2 --timeout 130s --metrics-brief
taskset -c 2 stress-ng --stream 1 --stream-l3-size 2M --stream-index 0 --timeout 130s --metrics-brief
taskset -c 2 stress-ng --cache 1 --cache-level 3 --cache-size 2M --cache-no-affinity --timeout 130s --metrics-brief
taskset -c 2,3 stress-ng --memrate 2 --memrate-bytes 64M --timeout 130s --metrics-brief
```

Retained per-run `E1_*_r1/condition.json` files in the PTY campaign record `exact_load`. Pipeline construction: `tools/experiments/e_campaign.py::stress_commands`. It starts separate single-worker commands on each listed CPU for CPU and Memrate (`taskset -c 2` and `taskset -c 3`, `--cpu 1` or `--memrate 1`); Stream and Cache flags are as above. Commands append `--metrics-brief`; the campaign owns their lifetime and terminates them after the pipeline finishes, rather than using the timer campaign’s 130 s timeout. Supporting definitions: `tools/timing/README.md` and `docs/research/R5.md`. These settings distinguish remote-core shared-resource pressure from contention on the measured core.
