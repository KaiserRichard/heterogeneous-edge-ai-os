## Numbered defects

1. **MAJOR — pages 15, 19 and 29: an inferred queue explanation becomes an established result.** Page 19 concludes that “the queue before inference determines accumulated age.” Page 29 labels “Bridge latest misses input queue” MEASURED, without distinguishing the measured zero replacements/completion intervals from the inferred location and cause of backlog. Page 15 also says the observations “locate” backlog upstream. `docs/STAGE_REPORT.md`, “Freshness: the queue was in the wrong place,” explicitly labels upstream accumulation **INFERRED**; the subsequent loaded input-policy trials are all INVALID for power and their clean benefit remains **UNKNOWN**. The measured observations are consistent with this explanation, but do not turn the intervention into a clean causal comparison. **Required:** retain MEASURED for the observed ages, intervals and zero replacements; label the upstream explanation INFERRED; state in the conclusion that a clean input-policy benefit remains UNKNOWN. Preserve the FLAGGED label on E3b. This is central to the answer to RQ2.

2. **MAJOR — page 17: the analyzer cross-check does not define the quantity plotted.** Both axes say only “Difference”; neither the caption nor the talk script identifies the two complete intervals or the subtraction direction. `tools/la/la_analyze.py::analyze` computes `delta_safe_us = uart_safe_us - mcu_safe_us`: analyzer **last physical UART byte end → both state GPIOs low**, minus MCU **last accepted heartbeat receipt → FAILSAFE STATE_EVENT timestamp**. Those endpoints are distinct. CRC-decoding the final frame as HEARTBEAT makes the starting reference comparable, but does not make byte completion identical to firmware receipt, or the decision timestamp identical to the GPIO edge. Without this definition, the headline 47.5–67.6 µs can be mistaken for echo-mapping accuracy or decision-to-output delay. **Required:** put a compact interval diagram or explicit difference definition on this slide, define the sign, and explain that the residual includes timestamp placement, reception/output delay and clock effects. Keep absolute calibration UNKNOWN. The numbers themselves reproduce correctly.

3. **MAJOR — page 29: the analyzer evidence row drops its FLAGGED qualification.** The row “10/15 matching analyzer references” is labelled only “MEASURED, scoped.” `results/README.md` expressly retains the logic-analyzer collection as **FLAGGED**, with no collection-wide validity promotion; page 17 correctly repeats that limitation. “Scoped” does not tell a reader which qualification applies and the Q&A claim map can be read independently. **Required:** carry the explicit collection FLAGGED qualification into this row, while distinguishing the calculated comparison of retained measured captures from a clean qualified campaign. Do not imply that matching frame types establish run validity.

4. **MINOR — pages 5, 9 and 11–15: contention treatments are named but insufficiently defined for the live argument.** The audience sees CPU, Stream, Cache and Memrate categories without a main-slide explanation of what each stresses or where it runs. Placement matters to the conclusion that contention on other cores still affects the measured task. The retained cyclictest summary and E1/E2 CSVs specify CPU 2/3 placements, a cache working set, and separate streaming/memory-rate stressors; this detail is largely confined to external evidence paths. **Recommended:** add a compact load key and stressed-core placement in the method, distinguishing the timer's CPU 0 and the pipeline's inference CPU 0/source–bridge CPU 1. Keep exact commands in backup or the evidence register. Every current slide serves the defense purpose, but the method-to-result link needs this explanation.

5. **MINOR — page 5, repeated scope on page 14: memory locking is ambiguous across P0/P1.** After bullets for P0 and P1, “Both pinned to CPU 1; memory locked” can mean both profiles, although the intended meaning is the P1 source and bridge. Retained `E2_P0_B0_idle_latest_r1/settings.json` reports source/bridge `locked_kib = 0`; the corresponding P1 file reports 2928 KiB each. Both profiles have source/bridge affinity CPU 1 and inference CPU 0. **Recommended:** say explicitly “P1 source and bridge: CPU 1, memory locked; P0 source/bridge: CPU 1, unlocked.” This also prevents describing E2 as a scheduling-class-only comparison when the applied profiles change locking.

6. **MINOR — pages 16–17: the most complex result plots use the smallest labels and weak visual discrimination.** At the full 1280-pixel rendering, the analyzer's rotated capture IDs and the E4 panel labels/ticks are substantially smaller than slide body text. E4 uses one color for all event reasons, including the mixed-reference F4 first events; several nearly coincident samples are difficult to distinguish visually. The caption says every point is a run, but a projected audience cannot readily count them or identify the heartbeat versus inference reference. **Recommended:** enlarge plot typography, simplify capture IDs, and use reason-coded symbols/colors or annotate the F4 split directly. Move secondary labels to backup if necessary. This is a projection/readability issue, not clipping or an incorrect statistic.
