Service = input-to-inference completion (includes input queue/pre/postprocessing). Delivery = input-to-reception. Latency cells: median of per-run P50 / median of per-run P99 / maximum observed maximum; nearest-rank per run. Other condition scalars/counts/rates: median per run; peak AoI and RAM: maximum. Counts are not pooled. CPU = median aggregate source/inference/bridge utilization (100% = one core); RAM = peak summed RSS. Drops = source/inference IPC drops + bridge queue drops; overflows = bridge queue drops (same events). Replaced = bridge overwritten; shutdown discards and missing deliveries are separately retained.

E3/E3B held-value AoI follows the freshest informative delivery, integrates stalls and final tail in the declared RAW-clock window. Before the first informative delivery AoI is undefined: uninitialized_seconds is retained; the time-average denominator is initialized_seconds. No zero-filled full-window AoI is claimed. Age-violation time columns use strict >100/>150 ms. Deadline misses are reception AoI >100/>150 ms, denominator all CRC-valid inference receptions including drain; missing deliveries are separately reported, not counted as receptions. Source period is 100 ms; measurement window excludes shutdown drain.

E3B fixes bridge policy to latest and compares input fifo/latest under P1 on idle and B2_memrate_c23. Reception P50/P99 use the same joined CRC-valid receptions as delivery latency. Skipped count is infer.csv status=skipped_stale; these records have no completion timestamp and are excluded from service latency/completion counts. Skips are separate from IPC drops, bridge replacements and deadline misses; reception counts include drain.

Validity requires complete monitor and applied-settings evidence, successful pipeline/stressors, no live bits (0xF), and no new sticky bits. Pre-existing sticky flags alone do not exclude a run. Exclusions remain on disk. CSV tables retain the exact deck columns; E2/E3 CSV row order and condition identities are in per_condition.csv; LaTeX adds matched-condition labels and valid repeat counts. Three repeats are the ticket default, below the deck acceptance gate of five valid repeats. P2 quotas: not done.
